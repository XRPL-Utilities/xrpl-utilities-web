How this works ▼

Understanding permissioned domains

What it is

A permissioned domain (XLS-80) is a ledger object that limits who can take part. Its owner lists the credential issuers it accepts, and only accounts holding a valid credential from one of them can trade inside it. XLS-81 adds a permissioned exchange that uses those domains.

Who uses them

Institutional liquidity venues, tokenized real-world-asset issuers, OTC desks that check identity, and regulated security tokens. The live directory above lists every one on mainnet.

How long it takes

The on-chain side is fast. Creating a domain is one transaction, confirmed in seconds, with a fee well under a cent and 0.2 XRP held in reserve while the domain exists.

The off-chain side is slower. A useful domain needs a credential issuer, legal review and a way to get credentials to participants: hours if self-issued, days to weeks with third-party identity checks.

How it works

Read straight from the ledger

Every permissioned domain on the validated XRP Ledger is in the directory. Nothing is added or left out by hand.

Where an owner is a known organization (a bank, asset manager or infrastructure firm), its name appears on the row. Otherwise you see the address.

Each domain links to XR-Sentinel so you can check how the owner's wallet behaves.

What XR-Trust is not

Descriptive directory, not a verdict

XR-Trust describes what's on-chain. We do not certify, endorse, or assess the legitimacy of any domain, owner, credential issuer, or member. Inclusion is not approval; absence is not disapproval. Not a compliance, AML, sanctions, or KYC determination; not legal or investment advice. Compliance, verification, and trust judgments remain with the consumer.

Membership in a permissioned domain is implicit (any address holding an accepted credential), and v1 does not estimate member counts.

# pip install x402-xrpl
from x402_xrpl import X402RequestsSession
from xrpl.wallet import Wallet

def pay_in_xrp(accepts, *_):
    return next(a for a in accepts
                if a["network"] == "xrpl:0" and a["asset"] == "XRP")

session = X402RequestsSession(
    wallet=Wallet.from_seed(seed),
    rpc_url="https://YOUR_XRPL_RPC",
    payment_requirements_selector=pay_in_xrp,
)

# look up a single domain by its 64-hex LedgerIndex
resp = session.post(
    "https://trust.xrpl-utilities.io/scan",
    json={"domain_id": "AB12…"},
)
resp.raise_for_status()  # a 402 here means the payment did not go through
record = resp.json()

for match in record["matches"]:
    print(match["owner_address"],
          match["accepted_credentials"])

Output shape

What you get back

  • domains[]: one record per permissioned domain, with its ID and owner wallet
  • owner_label: the operator’s public name and website when known
  • accepted_credentials[]: each credential the domain accepts, who issues it, and its type in plain text (for example KYC)
  • identity_tier: how much the operator has published about who it is, from institutional down to anonymous
  • A single-domain lookup adds when it was created and last changed, its trading activity, and the operator’s published identity
  • /credentials/issuers returns each issuer, the domains that accept it, and the credential types it has issued
